# TG Post Scheduler

Бот-планировщик постов для Telegram-каналов: загрузил контент → выбрал каналы →
назначил время публикации и автоудаления → бот сам всё сделал.

## Возможности

- **Русский / English** — выбор языка интерфейса при первом запуске и в «⚙️ Настройках»,
  переведён весь бот (меню, кнопки, все сообщения)
- Публикация текста / фото / видео / **альбомов** (несколько фото и видео в одном посте) по расписанию (или сразу)
- Форматирование текста и **premium-эмодзи** сохраняются как есть — публикация идёт через
  `copyMessage`/`copyMessages` (Telegram копирует оригинал один в один), а не пересборку ботом
- Один и тот же пост можно разослать сразу в несколько каналов одной кнопкой
- Автоудаление поста: 1/2/4/8/12/24/48/72 часа или без удаления — индивидуально для каждого канала
- **Редактирование текста** уже созданного поста через «📋 Мои посты» — включая посты, которые
  уже опубликованы (текст/подпись обновится "вживую" во всех каналах), медиа при этом не трогается
- **Удаление поста** из «📋 Мои посты» — сразу из всех каналов или только из одного (если разослан в несколько)
- **«📋 Мои посты» автоматически не показывает посты старше 30 дней** — и физически удаляет их
  из базы фоновой задачей (раз в несколько часов), но только если у поста не осталось
  ни одной запланированной, ещё не опубликованной цели — так не сотрёт то, что реально
  ещё должно выйти. Срок настраивается через `POST_RETENTION_DAYS`
- **«📣 /post_all»** — рассылка одного поста **лично каждому пользователю бота** (не в канал).
  Доступно только тем, чей Telegram ID указан в `ADMIN_TG_IDS`. `/post_all` — навсегда,
  `/post_all_24` / `/post_all_48` (или любое число часов) — с автоудалением у каждого получателя
- **🔕 Без звука / 🔔 Со звуком** — переключатель на экране предпросмотра, управляет
  `disable_notification` при публикации (подписчики не получат звук/вибро уведомления)
- **Удалить из комментариев** (в «⚙️ Настройки») — если бот добавлен и в канал, и в привязанную
  к нему группу обсуждений (с правом удаления сообщений там), при удалении поста из канала
  бот попробует найти и удалить и его копию-"эхо" в группе комментариев. Работает только
  для постов, опубликованных уже после включения этой настройки
- **Автоудаление собственных сообщений пользователя** — команды, промежуточные шаги
  (ввод даты, кнопок-ссылок, нажатия reply-меню) бот подчищает сам после обработки,
  чтобы не плодить вереницу. Сам контент поста (фото/видео/текст) не трогается —
  он нужен для копирования при публикации (сохраняет premium-эмодзи и форматирование)
- **Кнопки-ссылки под постом** — на экране предпросмотра «🔗 Добавить кнопку-ссылку»,
  формат `Текст - ссылка` (по одной на строку, несколько в ряд — через `|`); не работает
  для альбомов — ограничение Telegram (`sendMediaGroup`/`copyMessages` не поддерживают кнопки)
- **«✅ Во все»** при выборе каналов — не нужно тыкать галочку на каждый, если каналов много
- **Postoянное reply-меню** внизу экрана (Создать пост / Мои каналы / Мои посты / Настройки) —
  сначала выбираются каналы, потом присылается контент; точечная настройка при этом на инлайн-кнопках
- **Настройки на пользователя**: часовой пояс для ручного ввода времени, и опция автоудаления
  по умолчанию (подсвечивается ⭐ при создании поста)
- Медиафайлы не скачиваются и не проходят через сервер бота — используется Telegram `file_id`,
  поэтому нагрузка на сервер минимальна

## Как это устроено

- `bot/main.py` — точка входа, поднимает бота и два фоновых воркера
- `bot/scheduler.py` — воркер публикации (раз в N секунд проверяет БД на "пора постить")
  и воркер автоудаления (проверяет "пора удалить")
- `bot/handlers/` — команды и диалоги (aiogram FSM)
- `schema.sql` — схема Postgres, накатывается автоматически при старте

## Локальный запуск

```bash
python -m venv venv
source venv/bin/activate
pip install -r requirements.txt

cp .env.example .env
# впиши в .env свой BOT_TOKEN и DATABASE_URL (нужен запущенный Postgres)

python -m bot.main
```

## Деплой на Railway

1. Создай новый проект на Railway, подключи этот репозиторий (GitHub) или
   загрузи код через Railway CLI.
2. Добавь в проект плагин **Postgres** — Railway сам создаст переменную
   `DATABASE_URL` и подставит её в сервис бота (Variable Reference).
3. В переменных сервиса бота добавь:
   - `BOT_TOKEN` — токен из @BotFather
   - `TIMEZONE` (опционально, по умолчанию `Europe/Moscow`)
4. Railway автоматически определит `Procfile` и запустит `worker: python -m bot.main`.
   Отдельный веб-порт не нужен — это фоновый процесс с long polling, не веб-сервис.
5. При первом старте бот сам создаст таблицы в БД (`schema.sql` применяется автоматически).

Тарифа Hobby ($5/мес) с большим запасом хватает: бот не скачивает медиафайлы,
основная нагрузка — лёгкие вызовы Telegram Bot API и пара запросов к Postgres
раз в 20 секунд.

## Деплой на Northflank (бесплатно, без карты)

Northflank деплоит через Docker — `Dockerfile` уже в репозитории, ничего
дополнительно готовить не надо.

1. Регистрация на northflank.com — карта не нужна для бесплатного тарифа.
   При выборе облака — оставь **их собственное managed-облако** (не BYOC:
   BYOC — это подключение своего AWS/GCP/Azure аккаунта, лишняя сложность
   для простого бота).
2. Создай проект → добавь **Managed PostgreSQL addon** — Northflank выдаст
   строку подключения (`DATABASE_URL` в их терминах может называться иначе,
   смотри в разделе Connect / Credentials этого addon).
3. Создай **сервис** (Service, не Job/Cron) → источник — этот GitHub-репозиторий →
   Northflank сам увидит `Dockerfile` и соберёт образ.
4. Важно: у бота **нет** HTTP-порта — это фоновый процесс на long polling к
   Telegram. При настройке сервиса отключи/пропусти health-check по HTTP-порту
   (или укажи тип без порта), иначе платформа может решить, что сервис "не
   поднялся", и будет его перезапускать.
5. В переменных окружения сервиса добавь:
   - `BOT_TOKEN` — токен из @BotFather
   - `DATABASE_URL` — строка подключения от Postgres addon (шаг 2)
   - `TIMEZONE` (опционально)
6. Деплой — при первом старте бот сам создаст таблицы (`schema.sql`
   применяется автоматически, как и на Railway).

Бесплатный тариф — 2 сервиса без ограничения по времени работы (не засыпает),
ровно под связку "бот + база".

## Как пользоваться ботом

1. Добавь бота администратором в канал с правами **"Публикация сообщений"**,
   **"Редактирование сообщений других пользователей"** и **"Удаление сообщений"**
   (без права редактирования публикация и автоудаление всё равно будут работать,
   но правка текста уже опубликованных постов — нет).
2. «📢 Мои каналы» → «➕ Добавить канал» — бот выдаст **одноразовый код**.
   Опубликуй его любым сообщением прямо в канале — бот сам увидит публикацию,
   проверит права и подключит канал, а само сообщение с кодом удалит.
   (Это надёжнее пересылки: если пост в канале сам является репостом из другого
   канала, пересылка покажет исходный канал вместо нужного — специально поэтому
   основной способ именно через код, а не forward.)
3. «📝 Создать пост» → **сначала** отметь галочками, в какие каналы постить
   (можно сразу несколько) → потом пришли текст, фото, видео или альбом.
4. Выбери, когда удалить пост: 1/2/4/8/12/24/48/72 часа или никогда (звёздочкой ⭐
   отмечен вариант по умолчанию из «⚙️ Настроек», если задан).
5. Бот покажет **предпросмотр** поста таким, каким он реально будет опубликован —
   и тут же кнопки, когда публиковать: сейчас, через 1/3 часа, либо вручную
   (`31.12.2026 15:30`, в часовом поясе из настроек).
6. Готово — бот опубликует и (если назначено) удалит пост автоматически, без твоего участия.

Разделы меню:
- **📢 Мои каналы** — список, удаление и добавление каналов (через код)
- **📋 Мои посты** — список последних постов; выбери пост →
  «✏️ Изменить текст» (можно поменять текст/подпись даже у уже опубликованного поста,
  медиа не меняется, только текст) или «🗑 Удалить пост» (если разослан в несколько
  каналов — можно удалить везде или только из одного)
- **⚙️ Настройки** — часовой пояс (для ручного ввода времени) и автоудаление по умолчанию
- Команды `/start`, `/cancel` остаются рабочими как раньше

## Как сохраняются premium-эмодзи и форматирование

Публикация идёт через `copyMessage`/`copyMessages` — Telegram копирует твоё оригинальное
сообщение (то, что ты прислал боту) один в один на сервере, без пересборки через
`sendMessage`. Это надёжнее, чем передавать текст+entities вручную, и именно так
сохраняются premium-эмодзи. Требования по документации Bot API: у владельца бота
должен быть Telegram Premium (либо у бота куплен доп-юзернейм на Fragment) — без
этого custom-эмодзи не будут работать вообще нигде, даже в личных чатах.

Если текст поста правили после создания (через «📋 Мои посты»), для публикации
используется резервный путь — пересборка из file_id + текст + entities, поскольку
исходное сообщение в личке уже не соответствует новому тексту.

### Альбомы

Просто пришли боту несколько фото/видео одним сообщением (как обычно в Telegram —
выделяешь несколько файлов и отправляешь разом). Бот подождёт секунду-две, соберёт
все части в один альбом и дальше поведёт себя как с обычным постом: выбор каналов,
времени, автоудаления. Подписью станет текст, добавленный к любому из файлов альбома.

## Важно про удаление сообщений

Если бот — администратор канала с правом "Удаление сообщений", он может удалить
собственный пост в любой момент, без стандартного 48-часового ограничения Telegram
(это ограничение действует только для обычных участников без прав администратора).

## Возможные доработки

- Поддержка альбомов (несколько фото/видео в одном посте, media group)
- Редактирование уже запланированного, но ещё не опубликованного поста
- Просмотр списка всех запланированных постов с кнопкой отмены
- Часовой пояс на пользователя, а не глобальный
